# 易搜 OCR 搜索设计方案

## 1. 产品决策

用户按下 OCR 快捷键，框选屏幕上的文字，易搜识别后将结果填入现有搜索框。用户可以校对文字、切换搜索引擎，按 `Enter` 提交。同一套交互支持 RapidOCR 和 Windows 内置 `Windows.Media.Ocr`。

便携版建议默认使用 **RapidOCR + PP-OCRv6 tiny**，以实际屏幕样本的识别质量和资源占用决定是否改用 `small`。`Windows.Media.Ocr` 面向具备包标识的构建，语言可用性由系统 OCR 语言包决定。设置页显示当前构建可用的选项及原因。[Windows OCR 文档](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr)

## 2. 用户交互

### 入口与框选

- 在「设置 → 全局快捷键」添加「OCR 搜索」。建议默认键为 `Alt+Shift+O`，复用易搜现有的快捷键录制和冲突反馈。注册失败时，设置页保留可更改的入口。
- 在划词未读到文字、并打开空搜索框时，提供「框选识别」入口。由搜索框启动时，先隐藏易搜界面，再捕获屏幕。这个入口带入用户刚选定的搜索引擎。
- 快捷键触发一次屏幕快照。遮罩用十字光标、轻度压暗和清晰的选区描边标记范围。顶部只提示「拖动框选文字 · Esc 取消」。拖动四个方向都可框选，拖动期间按住 `Shift` 可以移动选框。
- 松开鼠标后提交识别。单击或面积为零时继续等待拖选。候选实现按显示器建立遮罩，允许选框跨屏，捕获和选区都使用同一套虚拟桌面物理像素坐标。鼠标跨过不同 DPI 的显示器时，边框与截取范围仍对应同一像素位置。

### 识别与确认

- 识别较慢时，在选框旁显示「正在识别…」，延迟约 150 ms 再出现。识别期间按 `Esc` 可立即关闭遮罩并恢复之前的焦点。切换到新一轮框选时，过期结果由请求编号过滤。
- 成功后关闭遮罩，在选区所在显示器打开易搜搜索框。优先放在选区附近，并限制在显示器工作区内。结果填入搜索框，光标置于末尾，用户可以直接修改。右侧沿用搜索引擎组件和无字模式。快捷键入口使用当前搜索引擎或默认引擎，划词入口使用当次搜索已经选定的引擎。
- 单行结果使用现有输入布局。多行结果默认展开为可滚动的编辑区，按 `Shift+Enter` 换行，按 `Enter` 提交。提交前整理行间空白，保留词间分隔。OCR 内容作为普通搜索文本处理，正文中的 `#` 不触发引擎别名。
- 结果区提供「重新框选」操作。再次框选会捕获当前画面，适合更换区域或读取下一条内容。关闭搜索框时结束这次识别会话。

### 异常反馈

| 情况 | 界面行为 |
| --- | --- |
| 区域里未识别到文字 | 保留画面和选区边框，提示「未识别到文字」，可立即重画选区。 |
| 截图失败或捕获接口明确拒绝 | 提示「无法捕获此区域」，可重试或关闭。正常的纯色区域仍按识别结果处理。 |
| RapidOCR 模型缺失或校验失败 | 打开 OCR 设置的入口，并指出需要修复的模型档位。 |
| Windows OCR 缺少包标识或所选语言包 | 设置页显示对应原因。缺语言包时提供跳转系统语言设置的入口。 |
| 识别后浏览器打开失败 | 在搜索框保留文字和引擎，用现有错误提示和重试流程处理。 |

## 3. 后端与模型

### RapidOCR

本地来源为 `D:\100_Projects\110_Daily\A-Crate\Rapid-OCR-RS\models\text`。每一档都由检测模型、识别模型和配套字典组成。下表是这三份文件的实际大小合计，估算 EXE 体积时还需计入推理运行时和封装开销。

| 档位 | 检测模型 | 识别模型 | 字典 | 合计 | 建议用途 |
| --- | --- | --- | --- | ---: | --- |
| `tiny` | `PP-OCRv6_det_tiny.onnx` | `PP-OCRv6_rec_tiny.onnx` | `ppocrv6_tiny_dict.txt` | 6.05 MiB | 默认候选，优先验证终端小字和中文报错。 |
| `small` | `PP-OCRv6_det_small.onnx` | `PP-OCRv6_rec_small.onnx` | `ppocrv6_dict.txt` | 29.79 MiB | 可选档。根据小字、混排和标点的实际收益决定是否提升为默认。 |
| `medium` | `PP-OCRv6_det_medium.onnx` | `PP-OCRv6_rec_medium.onnx` | `ppocrv6_dict.txt` | 132.39 MiB | 可选档。用于确有收益的识别场景和质量对照。 |

模型按档位成组加载，尤其要保持 `tiny` 的识别模型与其专用字典配对。复用 Rapid-OCR-RS 已有的文本检测、裁剪、识别与 CTC 解码，首版采用 CPU 推理。集成原型通过薄 C ABI 从 C++ 调用 Rust 文本接口，传入带行步长的屏幕像素。封装方式以实测的链接产物为准。模型、字典和原生依赖的包体与再分发条款分别核对，发布清单记录来源、版本和 SHA-256。[Rapid-OCR-RS 接口说明](../../A-Crate/Rapid-OCR-RS/README.md) · [第三方资产说明](../../A-Crate/Rapid-OCR-RS/THIRD_PARTY_NOTES.md)

便携交付优先验证「单 EXE 离线启动 + 内置 `tiny`」是否成立，重点检查 ONNX Runtime 原生依赖、模型资源的内存加载和冷启动。`small`、`medium` 可用本地模型包提供。若原型需要旁置运行时 DLL，交付物应明确标为便携目录版，并以干净环境的离线启动测试验收。[Rapid-OCR-RS 运行时说明](../../A-Crate/Rapid-OCR-RS/THIRD_PARTY_NOTES.md)

### Windows 内置 `Windows.Media.Ocr`

通过 C++/WinRT 调用 `OcrEngine`，在后台从内存像素构建 `SoftwareBitmap` 后调用 `RecognizeAsync`。用 `AvailableRecognizerLanguages` 获取已安装的 OCR 语言，设置页只列出可用项。「跟随系统」采用 `TryCreateFromUserProfileLanguages` 的选取结果。一次识别使用一个 `OcrEngine` 的语言配置，中英混排效果纳入实测。尺寸超过 `MaxImageDimension` 时等比缩放，优先保留小字细节。[OcrEngine 文档](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine)

微软将该桌面 API 的支持范围限定在具有包标识的应用。Windows OCR 入口按包标识和语言能力检测结果启用，显示实际采用的语言。切换后端由用户显式完成，识别失败时提示更改方式。[Windows OCR 命名空间](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr)

## 4. 架构与资源生命周期

```mermaid
flowchart LR
    A[快捷键或框选识别] --> B[捕获屏幕并框选]
    B --> C[后台识别]
    C -->|RapidOCR| D[统一为按行排列的文本]
    C -->|Windows OCR| D
    D --> E[搜索框编辑和选引擎]
    E -->|Enter| F[现有搜索与历史流程]
```

- **UI 层**使用 Win32 和 Direct2D 绘制遮罩，负责框选、取消与结果预览。遮罩在捕获完成后显示，随后按需重绘。复用现有搜索框、引擎菜单、快捷键录制和中英文资源。
- **平台层**提供屏幕捕获及两个 OCR 实现。两种后端接收同一份选区像素，返回有阅读顺序的文本行和错误状态。RapidOCR 的内部置信度可以用于排查和评测，界面以实际识别结果和错误状态为准。
- **执行层**管理一条按需启动的识别任务。从后台收到结果时核对请求编号，再交给 UI。取消可立即恢复 UI，若原生推理仍在进行，由工作线程收尾并释放资源。连续触发保留最新请求，后台串行执行以控制内存峰值。
- **搜索核心**扩展 `SearchOrigin::ocr`，沿用现有浏览器启动与搜索历史。仅在用户实际提交且允许记录历史时写入查询文字。快照、裁剪像素和识别中间结果只保存在内存中。每次识别结束后释放裁剪像素和中间结果，全屏快照在遮罩关闭时释放。
- **驻留资源**首次调用才初始化 OCR 后端。最近使用的模型会话短期复用，空闲后释放。具体缓存时长依据首次识别耗时、连续使用和托盘占用测试确定。

## 5. 设置与发布配置

在「设置 → 全局快捷键」加入 OCR 快捷键，在「设置 → OCR 搜索」加入后端选择。RapidOCR 显示 `tiny`、`small`、`medium` 的大小和可用状态，Windows OCR 显示语言选择和语言包状态。推荐在 INI 的 `[Shortcuts]` 保存 `Ocr`，在 `[OCR]` 保存 `Backend`、`RapidModel` 和 `WindowsLanguage`。本地模型包通过可选的 `RapidModelDir` 引用，相对路径以活动 INI 所在目录为起点。配置随现有导入、导出与自定义配置路径工作。缺项按当前可用后端的默认值加载。

## 6. 实施顺序与验收

1. **记录升级前基线。** 测量原有搜索框首次响应、空闲托盘私有工作集和后台 CPU 唤醒。保存快捷键、划词、剪贴板搜索、引擎切换及配置导入导出的回归结果。
2. **完成端到端交互。** 用固定文本结果验证框选、取消、原窗口焦点、搜索框落点、编辑和提交，再分别接入两个实际后端。便携版和包标识构建各自验证部署与缺依赖行为。
3. **比较四组识别结果。** 使用同一批标注截图测试 Windows OCR 与 RapidOCR 三档。覆盖简中、英文、中英混排、浅深色、终端小字、易混标点及图片里的报错。记录字符错误率，并单独检查路径、命令和错误码的完整性。保留同设备、同屏幕缩放、同一裁剪图像的测试条件。
4. **验证资源和异常。** 分别记录冷启动、热识别的中位数和 P95、峰值内存、最终发布体积，以及识别结束后回到托盘的占用。测 100%、125%、150% 缩放与混合 DPI 双屏，覆盖跨屏、快速取消再触发、无文字、模型缺失和运行时加载失败。
5. **运行升级后回归。** 重测既有入口，并验证 `框选 → 识别 → 编辑 → 换引擎 → 搜索`、重选、取消、历史开关及配置导入导出。默认档位以真实屏幕样本和驻留数据决定，模型文件大小和目标机性能都记录在验收结果里。
